# Q&A 准备稿 1.0

下面这份内容用于组内统一答辩口径。每个成员不需要逐字背，但至少要知道核心逻辑。

## 1. 为什么用仿真而不直接录真实高铁站？

因为真实高铁站或站台环境的噪声成分非常复杂，通常会同时包含人声、列车低频轰鸣、混响和广播系统本身的影响。  
如果一开始直接处理这种复杂环境，就很难用基础 low-pass filter 把问题讲清楚。

我们这次选择的是“真实应用背景 + 可控仿真”的方式。这样既保留了公共广播的现实意义，也能保证噪声特征可控、实验结果稳定，便于分析和展示。

## 2. 为什么选择高频 hiss，而不是更复杂环境噪声？

因为高频 hiss 在频域中更容易被识别，也更适合基础滤波器设计。  
它能帮助我们把展示重点放在“频域分析如何指导系统设计”上，而不是被复杂背景噪声的细节牵着走。

换句话说，这个项目不是想模拟所有现实噪声，而是先选一个最适合 Signals and Systems 解释的典型问题。

## 3. 为什么选择 low-pass？

因为在当前仿真设置里，hiss 噪声主要增强高频区域，而语音的主要信息集中在较低到中频范围。  
所以从频域上看，low-pass filter 是一个自然的第一选择。

它的优点是：

- 原理简单
- 频率响应容易解释
- 和课程中的系统观点联系紧密

## 4. 为什么选 3200 Hz？

我们比较了 `2800 Hz`、`3200 Hz` 和 `3600 Hz` 三组 cutoff。

- `2800 Hz` 压噪更强，但语音细节损失更多，听起来偏闷
- `3600 Hz` 语音更自然，但高频噪声残留更多
- `3200 Hz` 在噪声抑制和语音保留之间表现得更平衡

所以 `3200 Hz` 不是唯一可能的答案，但它是最适合作为课堂主 demo 的版本。

## 5. 为什么 3600 Hz 的某些指标更高，却没选它做主 demo？

因为课堂展示不能只看单一指标。  
虽然 `3600 Hz` 在输出 SNR 上更高，但它保留的高频成分也更多，因此 hiss 残留更明显。  
对于 demo 来说，`3200 Hz` 的前后差异更清楚，也更容易解释。

## 6. 这个项目为什么属于 Signals and Systems，而不只是调包做 DSP？

因为我们这次真正做的不是简单调用工具，而是完整地完成了以下过程：

- 建模：定义语音 + hiss 噪声场景
- 分析：用 Fourier Transform 看清频域结构
- 设计：选择滤波器类型和 cutoff
- 比较：测试多组参数
- 评估：用音频、waveform 和 spectrogram 说明系统效果
- 解释：把滤波器作为输入输出系统来理解

所以这个项目的核心是“信号分析 + 系统设计 + 输入输出解释”，而不是单纯的软件调用。

## 7. 这个方法的局限是什么？

它的局限主要有两个：

第一，low-pass filter 会在压制高频噪声的同时削弱一部分高频语音细节，所以它不可能做到完美恢复。  
第二，这种方法适合当前这种高频 hiss 场景，但如果噪声变成更复杂的环境噪声，单纯的基础 low-pass filter 就不够了。

## 8. 如果环境噪声更复杂怎么办？

如果噪声频率范围和语音高度重叠，或者噪声成分更加宽带、更加动态，那么更复杂的方法会更合适，比如：

- 更细致的滤波设计
- spectral subtraction
- adaptive filtering
- 更高级的 speech enhancement 方法

但这些超出了本项目当前的重点。我们这次更强调的是一个基础、可解释、适合课程展示的系统设计案例。
