# Improvement Checklist 1.0

这份清单不是为了推翻现在的项目，而是为了帮助你们在现有成果已经成型的基础上，继续把展示做得更稳、更清楚、更成熟。

## 1. Demo 层面的提升

- 再听一遍 `clean / noisy / filtered` 三段音频，确认课堂播放时前后差异足够明显。
- 如果 `filtered_voice.wav` 和 `filtered_voice_3200.wav` 内容一致，就统一只保留一个主版本，避免最后演示时混淆。
- 把最终上台播放的三段音频再裁成统一长度，建议每段 `3-4` 秒。
- 确保 PPT 中嵌入的音频和本地备用音频文件完全一致。
- 试一次真实设备播放，确认音量不会太小，也不会爆音。

## 2. 图表层面的提升

- 统一图表中 `clean / noisy / filtered` 的颜色逻辑，保持和 PPT 文字一致。
- 再检查 `waveforms_round1.png`、`spectrogram_round1.png`、`parameter_comparison_round1.png` 是否都足够清晰，避免投影时字太小。
- 如果时间允许，可以补一版“只截取 demo 那几秒”的局部放大图，比整段图更适合上台解释。
- 给每张最终使用的图配一句固定结论，避免上台时临场组织语言。

## 3. PPT 内容层面的提升

- 再压缩每一页的文字量，尤其是 `Motivation`、`Discussion`、`Conclusion` 这几页。
- 检查每页是否真的只有一个主结论，如果一页里有两个重点，就拆成“主结论 + 支撑说明”的结构。
- 确保 Slide 5、6、7、10、11 这几页的逻辑衔接是顺的，因为这是整场展示最关键的部分。
- 在 PPT 末尾保留 references 页或附页，哪怕不一定现场展开，也会让整个项目更完整。

## 4. 讲述层面的提升

- 每位成员都要会用一句话讲清楚：这个项目解决的到底是什么问题。
- 把 `3200 Hz` 的选参理由压缩成 20-30 秒可讲版本。
- 把“为什么这不是只调包”练熟，因为这是很容易被问到的问题。
- Demo 讲解要和图一一对应，不要出现“图讲图的，音频讲音频”的断裂感。

## 5. Q&A 层面的提升

- 全组统一回答口径，不要出现每个人说法不同的情况。
- 特别准备以下几个问题：
  - 为什么采用仿真而不是真实高铁站录音？
  - 为什么选择高频 hiss？
  - 为什么选择 low-pass？
  - 为什么最终选 3200 Hz？
  - 为什么这个项目属于 Signals and Systems？
  - 这个方法的局限是什么？
- 如果老师继续追问“更真实环境怎么办”，统一回答成“那需要更复杂方法，但已经超出本项目重点”。

## 6. 仓库与提交层面的提升

- 再确认一次仓库里没有无关缓存文件或临时文件。
- 把最终要保留的文件和不需要上云的文件分清楚。
- 如果后面还会继续改 PPT，建议在改动前复制一个新版本，不要直接覆盖唯一可用版本。
- 在提交最终 slides 前，确认 references、讲稿、音频和 PPT 是同步的。

## 7. 最后收口建议

如果时间有限，优先级建议这样排：

1. 试讲一遍，找出最不顺的地方  
2. 优化 demo 的音频与图对应关系  
3. 统一 Q&A 口径  
4. 最后再去微调 PPT 文案和版式

这一步之后，你们项目真正最重要的就不是“再做更多内容”，而是“把现有内容讲得更像一个完整作品”。
